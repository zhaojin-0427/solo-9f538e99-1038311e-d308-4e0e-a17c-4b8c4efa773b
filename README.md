# 波段查缺 API（FastAPI + SQLite）

植被指数（如 NDVI）要求**同一景**的红光（red）与近红外（nir）在同一网格像元上
都有效。本服务接收各景各波段的 0/1 有效掩膜，维护每像元的已提交覆盖，并按日期与
网格矩形返回连续缺口，供数据员补报。

## 启动

### Docker Compose（推荐）

```bash
docker compose up -d --build
```

- 服务：<http://localhost:8000>
- Swagger 交互文档：<http://localhost:8000/docs>（可直接在页面上提交掩膜与查缺）
- OpenAPI：<http://localhost:8000/openapi.json>
- SQLite 数据持久化在命名卷 `gapcheck-data`（容器内 `/data/gapcheck.db`）

### 本地直接运行

```bash
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
# 数据库路径可用环境变量覆盖：
```

## API

### `POST /masks` — 提交 / 更正某景某波段掩膜

请求体（JSON）：

| 字段 | 说明 |
| --- | --- |
| `date` | UTC 日期 `YYYY-MM-DD` |
| `scene_id` | 景号 |
| `origin_x` / `origin_y` | 景网格左上角在全局网格中的坐标 |
| `band` | `red`（红光）或 `nir`（近红外），两波段可分别提交、分别更正 |
| `mask` | 行优先二维 0/1 数组，宽、高各不超过 256 格，行长度必须一致；1=有效 |

规则：

- **同景的网格位置与尺寸固定**：首次提交注册几何；之后同景号/同日期再提交若
  原点或宽高不一致，返回 `409`，不写入任何数据。
- 更正只回读**本景**的源掩膜（另一波段），只重算**本景范围**内的覆盖；其他景的
  贡献原样保留。
- 整个提交在一个 SQLite 事务（`BEGIN IMMEDIATE`）内完成，任何失败都回滚，
  已提交结果仍可查询。

### `POST /repairs` — 按源掩膜修复矩形内的已提交覆盖

从备份补回源掩膜后，`coverage` 表可能已与掩膜不一致（查缺结果过时）。本接口
按 UTC 日期与网格矩形（宽、高各 1–256 格）重算覆盖。

请求体（JSON）：

| 字段 | 说明 |
| --- | --- |
| `date` | UTC 日期 `YYYY-MM-DD` |
| `origin_x` / `origin_y` | 矩形左上角网格坐标 |
| `width` / `height` | 矩形宽、高（格），1–256 |

规则：

- **以相交景的源掩膜为准**：取所有与该矩形有交集的景，逐格重建红光 / 近红外的
  景号集合。
- **只改有差异的格**：逐格比对已提交覆盖与掩膜推导出的集合，相等则不动；不等
  则改写。即使缺口**类别**没变（例如仍为 `red_only`），只要景号集合不同也修正。
- **返回逐格差异**：每个改动格给出 `x`、`y`，以及 `red_added` / `red_removed` /
  `nir_added` / `nir_removed` 景号列表；另含 `cells_checked` 与 `cells_changed`。
- **重算期间仍可补报**：读取阶段使用只读快照事务，不阻塞写入；写回阶段用
  `BEGIN IMMEDIATE` 后先做冲突检查再写。
- **冲突判定**：修复开始（取快照）后，若有补报改变过矩形内任一景、任一波段、
  任一格的有效位，返回 `409`——**即使之后又改回**也算冲突；矩形外的改动不影响
  修复。
- **写回不重读源掩膜**：写回阶段只使用读取阶段得到的集合。
- **原子性**：冲突检查、写回、写后核对在同一事务内；冲突或写入失败全部回滚，
  不留下本次修复的任何改动。
- **写后核对**：写入完成后在同一事务内重新读取矩形覆盖，逐格与掩膜集合比对；
  不符则整体回滚并报错。
- **源数据校验**：若补回的源掩膜字节数与已登记几何不符，修复以 `500` 中止且
  不写入任何改动。

### `GET /gaps` — 按日期与矩形查缺

查询参数：`date`、`origin_x`、`origin_y`、`width`、`height`
（矩形宽、高各不超过 256 格）。

判定：任一景的红光与近红外在某格都有效（两景号集合有交集），该格即**齐全**。
其余格子按缺口类别，在每一行内把连续同类格子合并成段返回：

| category | 含义 |
| --- | --- |
| `red_only` | 仅红光有效，缺近红外 |
| `nir_only` | 仅近红外有效，缺红光 |
| `different_scenes` | 两波段都有，但分属不同景，没有同一景的双波段 |
| `both_missing` | 红光与近红外均缺报 |

返回含每类计数、齐全格数与逐行连续缺口段（`y`、`x_start`、`x_end`、`length`）。

### `GET /scenes/{date}/{scene_id}` — 回读某景几何与已提交波段信息


## 数据模型与关键保证

SQLite 四张表（见 `app/db.py`）：

- `scenes`：每景固定几何（日期、景号、原点、宽高）。
- `band_masks`：每景每波段一份源掩膜 BLOB（行优先 0/1），更正按波段覆盖。
- `mask_changes`：补报使某波段有效位发生翻转的审计记录（每翻转一次一行，
  记录翻转格坐标与边界框，自增 `seq` 作为修复的冲突判定基准）。修复据此判断“开始后是否有人改过区内有效位”，
  从而使“先改再改回”也能被识别为冲突。
- `coverage`：每像元一行（`date,x,y` 主键，`WITHOUT ROWID`），`red_scenes` /
  `nir_scenes` 为提供有效样本的**景号 JSON 数组**。这是更正时无需读取其他景掩膜
  的关键：本景旧贡献从两个数组中移除，再按新掩膜加入即可。

对应需求的落点：

1. **掩膜和覆盖一起生效，失败仍可查原结果** — 单事务提交，异常即回滚。
2. **查询取同一已提交状态，无需读取单景掩膜** — `/gaps` 只查 `coverage` 表，
   单条带索引的范围扫描；WAL 模式下读不阻塞写，一条查询对应一个已提交快照。
3. **读取的覆盖记录最多和矩形内像元一样多** — 扫描条件为
   `x BETWEEN ... AND y BETWEEN ...`，主键即 `(date,x,y)`，每像元至多一行；
   无覆盖的像元按“两波段都缺”处理，不产生额外记录。
4. **更正仅重算本景范围** — 覆盖扫描与回写都限定在本景原点与宽高内，
   且只读取本景另一波段的源掩膜。
5. **尺寸限制** — 掩膜、查询矩形与修复矩形的宽、高均在 Pydantic / 查询校验中
   限制为 1–256。
6. **修复以源掩膜为准、只改差异格** — 读取阶段取相交景的掩膜重建集合，写回
   阶段逐格比对；集合不同即改写，与缺口类别是否变化无关。
7. **修复期间可补报、冲突可判** — 读快照不阻塞写；写前用 `mask_changes` 的
   `seq` 判定“开始后是否改过区内有效位”，改回也算；区外改动忽略。
8. **修复原子且写回不重读掩膜** — 检查、写回、写后核对同一事务；冲突与任何
   写入失败全部回滚。

## 测试

```bash
python -m pytest tests/ -q
```

覆盖：四类缺口分类、行内连续段合并、同景双波段齐全、跨景不同景判定、多景任一
齐全、更正只影响本景、几何冲突 409、失败回滚后原结果可查、256 上限、日期隔离
等 15 个基础用例；以及修复接口的 14 个用例：无需修复时零改动、按掩膜还原被篡改
的覆盖、类别不变但景号集合不同也修复、矩形尺寸校验、区内补报冲突（服务层与
HTTP 409 两种）、改回仍冲突、区外改动不冲突、写回不重读源掩膜、写入失败全量回
滚、直接改源表后重建过时覆盖、`different_scenes` 格的景号更正、响应差异与数据库
实际前后差异逐格核对、源掩膜长度与几何不符时 500 且不留改动。
